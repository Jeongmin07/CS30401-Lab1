# One extra final original segment during a selective loss wait

Experimental opt-in `ns3::TcpSocketBase::OrbitTailAdmission`, default false. It permits at most one extra original segment per active shared-wait episode after ordinary ACK-driven sending has used its normal allowance. It requires unique new SACK progress, application close-on-empty/send shutdown, one MSS or less unsent payload, sequence-based receiver-window compliance, and `pipe+payload <= cwnd+MSS`. The admission action itself does not change cwnd, fabricate delivered/PRR credits, or extend the loss deadline; native sending and subsequent recovery retain their normal accounting and RTO paths. Native later cwnd trajectories can differ. This is not RFC8985 TLP.

Read the [predeclared ten conditions](../../docs/experiments/20261013-orbit-tail.md). Existing orbit-loss files and runs remain unchanged. The standalone combined patch is based on the exact final V2 SHA recorded there. Development, runtime and input receipts must precede the first simulation; publication is owned by the parent task.

The final ten simulations completed on one immutable patched runtime. For 20 MSS with a false hint and actual first loss, FCT was 0.251509920 s baseline, 0.350482400 s selective, 0.257223678 s selective+tail. Exactly one 1380-byte original tail was admitted after ordinary credits were exhausted, with flight 13800→15180 bytes and admission-time cwnd 13800 unchanged. Native subsequent recovery changes the cwnd trajectory. The 21 MSS boundary and 100 GB LEO bulk conditions admitted no tail; their legacy measurements match the corresponding selective controls. The extra packet's own loss, zero-window/FIN boundary, ECN/RTO intervention and deployment safety are untested.
