# Vegas 갱신 후 혼잡 추정 여유 보존 — v2

상태: 실행 전 가설/비교 조건 기록. PR14의 같은 문제에 대한 후속 검증이며 v1 기록은 보존한다. 팀 최종 연구 주제나 병합을 확정하지 않는다.

v1은 LEO에서 큰 처리량 이득을 보였지만, 최근 최소 SRTT 전체를 기준으로 쓰면서 CUBIC이 만든 큐를 일부 기준 지연으로 흡수했다. 이번에는 기준을 올릴 때도 원래 Vegas의 beta=4 패킷 혼잡 추정 여유를 남긴다. 현재 window w와 20 유효 cycle 최소 R에서 C=floor(R*(w-4)/w)를 사용하며, 기존 상승 조건1ms/20cycles는 유지한다. 새로운 최적값 탐색은 하지 않는다. 이 여유는 실제 큐 길이가 아니라 Vegas 내부 추정이다. 지속 큐를 식별하거나 기준값의 누적 상승을 막는 보장은 없다.

[실행 전 비교 조건과 재현 코드](../../code/vegas-study/v2/README.md)에 10개 대조군과 v1 호환성 조건을 기록했다. 다른 조원은 PR14와 v1 근거를 먼저 읽고, 이번 변경이 무엇을 보장하며 무엇을 보장하지 않는지 검토하면 된다. 내부 AI 검토는 다른 두 조원의 실제 검토를 대신하지 않는다.

관측 결과, 비용, 원본 링크와 정확한 launch commit은 실행·독립 분석 후 추가한다.
