# 현재 연구 방향과 공통 계획

## 2026-10-12: 현대 TCP의 동적 경로 대응으로 방향 전환

이번 작업을 요청한 조원은 **BBR의 경로 합류 대응을 우선 진단**하고, 현대 TCP와 직접 연결되는 문제로 연구 중심을 바꾸도록 승인했다. 이 PR은 그 방향과 근거를 다른 조원에게 공유하고 검토받는 문서다. 팀 전체의 최종 주제·수치·역할을 확정한 것은 아니다.

- 주 질문: 위성 이동으로 별개 경로의 통신들이 같은 병목을 공유하게 될 때, 제공 BBR의 이전 대역폭 추정과 탐색 송신이 큐·손실·일시적 분배 불균형을 만드는가?
- 순서: **현상 진단 → TCP 설계와의 원인 연결 → 작은 개선 하나 → 동일 조건 비교**. 개선안을 먼저 만들거나 성공할 때까지 임의로 조건을 키우지 않는다.
- 구현 범위: 공식 환경의 `TcpBbr`은 BBRv1 계열이다. 최신 BBRv3 전체의 문제나 개선이라고 일반화하지 않는다.
- 기존 Vegas 연구는 결과와 재현 자료를 보존하되 이번 작업의 핵심 후보에서 제외한다. Handout STEP 1의 `state-of-the-art TCP implementations`, 관련성·시의성 요구에 비해 Vegas를 주제로 선택할 근거가 약하다. 기존 PR #14/#15를 임의로 닫거나 다른 조원의 작업 범위를 바꾸지 않는다.
- 먼저 실제 공유 경로와 피해를 찾는다. 자연 합류가 없거나, 고정 경로의 일반 경쟁과 구분되지 않거나, 기존 BBR이 충분히 잘 적응하면 합류 개선 구현을 중단한다.
- 대안: CUBIC HyStart 기동 조기 종료, BBR RTprop 갱신 지연과 실제 전송량 제한, BBR ProbeRTT의 서비스 감소 비용. 각각 관측과 구현 조건을 먼저 확인하고 별도의 중단 기준을 적용한다.

상세 근거와 후보별 판단은 [현대 TCP 연구 방향](research/20261012-modern-tcp-direction.md), 실제 진행·예산·남은 일은 [BBR 작업 기록](work/20261012-bbr-route-kim-seongchan.md)을 읽는다. 열린 Draft PR에는 아직 `main`에 없는 최신 코드와 결과가 있다.

### 이번 진단의 예산과 확인 기준

1. 제공 state의 metadata와 소수 경로부터 읽는다. fstate가 delta면 과거 갱신을 누적해야 하므로, 중간 파일 하나를 완전한 snapshot으로 취급하지 않는다. 읽은 파일·행·바이트·시간과 중단 예산을 기록한다.
2. 제공 서울–런던 state는 지상국이 둘뿐이다. 같은 지상국 쌍의 두 flow는 상시 같은 경로를 쓰므로 **서로 다른 경로가 자연 합류하는 실험으로 부르지 않는다**. 초기 공유 병목 진단과 자연 경로 합류 검증을 구분한다.
3. 100 Mbit/s·100-packet 큐는 기존 탐색 결과와 이어 비교할 출발점이며 현실 Starlink 용량을 보정한 값이 아니다. seed·flow 시작·평가 창을 실행 전에 선언한다.
4. BBR의 상태·대역폭/RTT 추정·송신 속도·cwnd/inflight와 실제 수신량·큐·drop을 함께 기록한다. 관측 코드가 기존 TCP 동작을 바꾸지 않는지 원본 실행과 대조한다.
5. 평균 처리량뿐 아니라 경쟁 시작/합류 구간의 두 flow 전달량·큐 대기·손실·안정화 시간을 본다. 아직 효과 수치는 없으며, 단독 평균 93.4 Mbit/s는 경쟁 성능을 보증하지 않는다.
