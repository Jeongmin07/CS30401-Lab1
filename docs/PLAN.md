# 현재 연구 방향과 공통 계획

## 2026-10-12 최신 판단: 예측 구간의 손실 판정과 제한된 복원 검증

사용자의 인과관계 검토를 반영해 **가용 대역폭 감소만을 근거로 한 BBR 경로 합류 개선 가설을 중단**한다. 같은 서비스/ACK/손실 이력이면 지상망의 경쟁 진입과 송신자가 보는 문제는 같다. 과제가 LEO에서만 발생하는 결함을 요구하는 것은 아니지만, 이번 주방향에는 LEO와 연결되는 추가 원인을 충분히 제시하지 못했다.

후속 피드백을 반영해 송신 pause/pacing 후보를 우선 제외한다. 현재 검증은 **기하 예측에서 전환·보호 구간을 정하고, 그 구간에서 SACK/dupACK 손실 판정 문턱을 높였다가 종료 때 기존 손실 증거를 재평가하는 방법**이다. 기존 K8/K20도 이미 notified window 방식이었다. 새 차이는 자동 구간 계산과 복원이 오래 미뤄지는 문제의 제한이며, 같은 아이디어를 새 발명으로 주장하지 않는다. opt-in 구현·빌드는 완료했고 실험 결과는 [현재 실행 기록](experiments/20261012-forecast-loss.md)에 갱신한다. Handout 4쪽과 Guide 14쪽은 미래 정보를 사용하는 접근을 허용하지만 정보 취득 방법·오차·배치 비용과 실제 효과는 설명/검증해야 한다.

자세한 후보 비교·선행연구·중단 기준은 [예측 가능한 LEO 정보를 활용하는 방향](research/20261012-predictable-leo-tcp.md)을 읽는다. 다른 조원이 최종 방향을 승인한 것으로 표시하지 않는다.

현재 [13개 완료 결과](experiments/20261012-forecast-loss.md)는 첫 LEO episode의 불필요한 복구 감소와 작은 전체 처리량 이득, 기존 보호의 복원 지연 감소를 보여준다. 실제 손실에서는 새 방법도 원본보다 느리다. "극적 처리량 개선"이나 모든 경우의 우월함을 보고서 결론으로 삼지 않는다. 마감 전에는 새로운 sweep보다 이 효과·비용·필요 정보와 재현 근거를 팀 검토에 전달하는 데 집중한다.

- **예측 구간의 손실 오판 완화:** 제공 CUBIC/SACK/PRR에서 확인된 episode를 사용한다. 종료 때 K3만 강제로 복원하면 남은 dupACK·SACK 정보로 assertion/복구 누락이 생길 수 있어 기존 증거를 재평가한다. 실질적으로 새 ACK를 만들거나 RTO를 정지하지 않는다. 실제 손실의 finite FCT 비용과 구간 종료를 함께 확인하며 큰 처리량 개선을 가정하지 않는다. Guide의 5.4초 그림만으로 허위 복구를 입증하지 않는다.
- **궤도 기반 BDP/BBR RTprop:** 제공 경로의 전파 RTT는 87.454–98.535ms, 최대/최소 비율은 약 1.127이다. ProbeBW cwnd gain 2를 고려하면 순수 기하 증가가 옛 BDP 상한을 바로 넘는다는 전제는 약하다. 이 조건의 대규모 실험은 진행하지 않는다. 혼잡·복구·대역폭 추정의 별도 문제는 제외한 분석적 선별이다.
- **CUBIC HyStart:** 과제 delay 검출은 최소 RTT 자체만큼 추가 지연을 요구해, 관측된 3–7ms 기하 상승만으로 조기 종료를 기대하기 어렵다. ACK train 분기는 미검증 대안으로 남긴다.
- **앙각 기반 제어:** 기본 모델의 앙각은 가시성·연결 조건이며 링크 용량/오류율과 연동되지 않는다. 근거 있는 무선 모델 없이 앙각으로 cwnd 상한을 내리는 후보는 진행하지 않는다. 연결 전환 예측의 보조 정보로는 검토할 수 있다.

### 보존할 초기 BBR 진단

제공 state 전체 delta 내용은 약134KB이고 읽기/경로 추적은 약0.1초였다. 두 도시 조합·각8시점의 별도 기하 계산은 합계 약10.9초였으며, 표본에서 자연 합류·분리 후보를 찾지 못했다. 샘플 사이 변화를 부정하는 결론은 아니다. 새 대규모 state는 생성하지 않았다.

BBR의 원본/관측 off/on 단독40초 실행은 기존 측정 CSV4개가 byte-identical했고 실제 수신량·큐 보존 검사도 통과했다. 처음 관측 실행의 패킷 UID 식별 오류는 고쳤다. 2-flow 진단은 180초 예산에서 timeout되어 불완전 결과로 보관했고, 동시에 시작하는 조건은 실행하지 않았다. 이 자료는 개선 효과나 LEO 특유의 결함을 입증하지 않는다. [관측 도구와 재현 명령](../code/bbr-route/README.md), [실험 기록](experiments/20261012-bbr-route-pilot.md).

## 초기 검토 기록: BBR 경로 합류 가설 — 현재 중단

이번 작업을 요청한 조원은 처음에 BBR의 경로 합류 대응을 우선 진단하도록 승인했다. 아래는 그 초기 판단의 기록이며, 위의 최신 판단과 중단 사유를 먼저 읽는다. 이 PR은 근거와 결과를 다른 조원에게 공유하고 검토받는 문서이며 팀 전체의 최종 주제·수치·역할을 확정하지 않는다.

- 주 질문: 위성 이동으로 별개 경로의 통신들이 같은 병목을 공유하게 될 때, 제공 BBR의 이전 대역폭 추정과 탐색 송신이 큐·손실·일시적 분배 불균형을 만드는가?
- 순서: **현상 진단 → TCP 설계와의 원인 연결 → 작은 개선 하나 → 동일 조건 비교**. 개선안을 먼저 만들거나 성공할 때까지 임의로 조건을 키우지 않는다.
- 구현 범위: 공식 환경의 `TcpBbr`은 BBRv1 계열이다. 최신 BBRv3 전체의 문제나 개선이라고 일반화하지 않는다.
- 기존 Vegas 연구는 결과와 재현 자료를 보존하되 이번 작업의 핵심 후보에서 제외한다. Handout STEP 1의 `state-of-the-art TCP implementations`, 관련성·시의성 요구에 비해 Vegas를 주제로 선택할 근거가 약하다. 기존 PR #14/#15를 임의로 닫거나 다른 조원의 작업 범위를 바꾸지 않는다.
- 먼저 실제 공유 경로와 피해를 찾는다. 자연 합류가 없거나, 고정 경로의 일반 경쟁과 구분되지 않거나, 기존 BBR이 충분히 잘 적응하면 합류 개선 구현을 중단한다.
- 대안: CUBIC HyStart 기동 조기 종료, BBR RTprop 갱신 지연과 실제 전송량 제한, BBR ProbeRTT의 서비스 감소 비용. 각각 관측과 구현 조건을 먼저 확인하고 별도의 중단 기준을 적용한다.

상세 근거와 후보별 판단은 [현대 TCP 연구 방향](research/20261012-modern-tcp-direction.md), 실제 진행·예산·남은 일은 [BBR 작업 기록](work/20261012-bbr-route-kim-seongchan.md)을 읽는다. 열린 Draft PR에는 아직 `main`에 없는 최신 코드와 결과가 있다.

### 이번 진단의 예산과 확인 기준

1. 제공 state의 metadata와 소수 경로부터 읽는다. fstate가 delta면 과거 갱신을 누적해야 하므로, 중간 파일 하나를 완전한 snapshot으로 취급하지 않는다. 읽은 파일·행·바이트·시간과 중단 예산을 기록한다.
2. 제공 서울–런던 state는 지상국이 둘뿐이다. 같은 지상국 쌍의 두 flow는 상시 같은 경로를 쓰므로 **서로 다른 경로가 자연 합류하는 실험으로 부르지 않는다**. 초기 공유 병목 진단과 자연 경로 합류 검증을 구분한다.
3. 100 Mbit/s·100-packet 큐는 기존 탐색 결과와 이어 비교할 출발점이며 현실 Starlink 용량을 보정한 값이 아니다. seed·flow 시작·평가 창을 실행 전에 선언한다.
4. BBR의 상태·대역폭/RTT 추정·송신 속도·cwnd/inflight와 실제 수신량·큐·drop을 함께 기록한다. 관측 코드가 기존 TCP 동작을 바꾸지 않는지 원본 실행과 대조한다.
5. 평균 처리량뿐 아니라 경쟁 시작/합류 구간의 두 flow 전달량·큐 대기·손실·안정화 시간을 본다. 아직 효과 수치는 없으며, 단독 평균 93.4 Mbit/s는 경쟁 성능을 보증하지 않는다.

아래는 병합된 자료와 아직 합의가 필요한 공통 사항이다.
