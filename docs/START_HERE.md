# 다른 조원의 AI에게 처음 알려줄 내용

우리는 CS30401 Lab 1을 함께 수행하는 조원 3명이다. 각자 자기 노트북에서 AI를 사용한다. 서로의 채팅이나 로컬 파일은 공유되지 않으므로, GitHub를 통해 **누가 무엇을 하는지, 어떤 코드가 작성됐는지, 어떤 실험 결과가 나왔는지** 확인한다.

별도의 AI 통신 시스템을 만들 필요는 없다. 각 AI가 작업을 시작하고 중요한 단계로 넘어갈 때 최신 Issue, Draft PR, 브랜치와 기록을 읽도록 한다. 조원이 작업을 지시하고 필요한 인수인계를 연결한다.

## 새 AI 채팅에 붙여 넣을 프롬프트

아래에서 담당자와 작업만 바꿔 사용한다. GitHub에 진행 상황을 공유하고 PR을 제출하도록 허용하는 문구가 포함되어 있으므로, 실제로 허용할 때 사용한다.

```text
우리는 조원 3명이 각자 노트북에서 AI와 함께 CS30401 Lab 1을 진행하고 있어.
다른 AI들은 다른 조원들의 별도 채팅이고, 서로의 로컬 작업은 자동으로 공유되지 않아.
공통 저장소는 https://github.com/Jeongmin07/CS30401-Lab1 이야.

내 GitHub 아이디: [담당 조원의 아이디]
이번 작업: [담당 Issue 번호 또는 구체적인 목표]
수정할 범위: [파일/기능/실험 범위]

먼저 README.md, AGENTS.md, docs/TEAM_WORKFLOW.md, docs/PLAN.md를 읽어줘.
GitHub의 진행 중인 Issues와 열린 PRs, 특히 Draft PR도 확인해서
다른 조원들이 하는 작업과 이미 공유한 코드·실험 결과를 파악해줘.
로컬 main에 아직 없는 내용은 해당 PR의 diff와 브랜치 파일을 읽어줘.
이미 한 작업을 반복하거나 같은 파일을 동시에 수정할 가능성이 있으면 알려줘.

이번 작업의 진행 상황을 담당 Issue에 기록하고,
내 작업 브랜치에 commit/push해서 Draft PR로 공유하는 것을 허용할게.
같은 작업의 후속 수정은 그 브랜치에서 계속하고,
의미 있는 결과와 막힌 점을 docs/work/[내 GitHub 아이디].md에 남겨줘.
실험 결과에는 실행한 코드 commit, 정확한 설정·명령·수치·한계를 기록해줘.
가설과 실제 관측을 구분하고, 하지 않은 실험을 했다고 쓰지 말아줘.
완성되면 검토 가능한 PR을 제출하고, main 병합은 조원들이 확인하도록 남겨줘.
```

## 다른 AI의 작업을 이어서 확인시키는 프롬프트

```text
이번 작업을 계속하기 전에 최신 원격 상태와 진행 중인 Issue/PR을 확인해줘.
특히 [PR 번호/Issue 번호]의 코드와 실험 기록을 읽고,
우리 작업에 영향을 주는 변경, 재사용할 수 있는 결과, 아직 검증되지 않은 가설을 정리해줘.
기존 로컬 변경은 보존하고 담당 작업 범위 안에서 계속 진행해줘.
```

외부 AI가 GitHub에 접근할 수 없으면 조원이 해당 PR diff와 기록을 전달한다. 이때 전달한 commit을 적고, 최신 원격 상태는 확인하지 못했다고 표시한다.
