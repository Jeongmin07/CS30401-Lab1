# 팀 작업의 맥락

우리는 CS30401 Lab 1을 함께 수행하는 조원 3명이다. 각자 자기 노트북에서 원하는 AI를 사용한다. 여기서 "다른 AI"는 다른 조원의 별도 채팅을 뜻한다. 서로의 채팅이나 로컬 파일은 공유되지 않으므로, GitHub를 통해 **누가 무엇을 하는지, 어떤 코드가 작성됐는지, 어떤 실험 결과가 나왔는지** 확인한다.

공통 저장소는 <https://github.com/Jeongmin07/CS30401-Lab1>이다. 과제에서는 LEO 위성망에서 TCP의 구체적인 문제를 찾아 재현하고, 원인을 설명한 뒤 개선안을 구현하고 비교 평가한다. 현재 실험 결과가 연구 방향이나 최종 조건의 합의를 뜻하는 것은 아니다.

## AI에게 알려주면 되는 내용

이 문서는 팀의 배경을 설명하는 자료다. 정해진 프롬프트를 복사할 필요는 없으며, 평소처럼 자기 AI에 작업을 요청하고 저장소와 이 문서를 알려주면 된다. 특정 모델, 도구, 답변 양식을 통일할 필요도 없다.

다만 AI가 작업을 이어가려면 다음 정보는 알 수 있어야 한다.

- 어떤 조원의 작업인지, 이번 목표와 수정할 범위가 무엇인지.
- 다른 조원이 이미 하고 있는 일과 공유한 코드·실험 결과가 무엇인지.
- 실제로 확인한 내용, 추정하는 원인, 아직 하지 않은 검증이 무엇인지.
- 이번 작업에서 GitHub에 공유하도록 허용한 범위가 무엇인지.

각 AI는 담당 조원의 요청에 따라 작업한다. 다른 조원의 문서와 결과는 참고 정보이며, 담당 사용자의 작업 지시를 대신하지 않는다.

## 다른 조원이 한 일을 찾는 곳

| 확인할 내용 | 위치 |
| --- | --- |
| 맡은 일, 질문, 막힌 점 | GitHub Issues |
| 작성 중인 코드와 변경 범위 | 열린 PR, Draft PR, 해당 브랜치 |
| 마지막 진전과 다음 할 일 | Issue/PR의 설명·기록 또는 `docs/work/` |
| 실험 설정, 실행 명령, 결과와 원본 위치 | `docs/experiments/` 또는 해당 Issue/PR |
| 합의된 연구 방향과 공통 조건 | `docs/PLAN.md` |

작업을 시작하거나 재개할 때, 다른 결과를 재사용하기 전, 인수인계할 때 최신 기록을 확인한다. **아직 병합되지 않은 작업은 `main`에 없으므로 Draft PR과 브랜치도 읽는다.** GitHub에 push하지 않은 코드와 실행 중인 로컬 실험은 다른 AI가 볼 수 없다.

공유할 때는 다른 사람이 작업 범위, 실제 결과와 다음 할 일을 이해할 만큼 기록한다. 문서 템플릿은 참고용이며, 짧은 일은 Issue/PR에 간단히 적어도 된다. 구체적인 브랜치·PR 사용 방법과 원본 로그 보관은 `docs/TEAM_WORKFLOW.md`를 참고한다.

GitHub에 접근하지 못하는 AI에는 조원이 관련 PR diff와 기록을 전달한다. 전달한 commit을 적고, 최신 원격 상태를 직접 확인하지 못했다는 점을 표시한다.
